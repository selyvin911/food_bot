# PublicFitness

Публичный дневник питания — компонент `Day Plate.dc.html` из Claude Design, собранный как
mobile-first сайт на Astro, который получает данные из API food-tracker **на этапе сборки**.

## Запуск

```bash
npm install
cp .env.example .env      # вписать токен в FOOD_TRACKER_ACCESS_TOKEN
npm run dev               # localhost:4321
npm run build             # запрашивает данные, пишет dist/
npm run preview           # отдаёт dist/
npm run check             # astro check
```

## Как данные попадают на страницу

`npm run build` один раз вызывает эндпоинт, преобразует ответ и запекает результат в HTML.
Браузер с API не общается — в готовой странице нет ни запроса, ни URL, ни токена.

```
GET https://food-tracker.pht.space/api/v2/recommendation/calc/board/
      ?dates=<ISO-даты через запятую>&week_render=<n>
Authorization: Secret <FOOD_TRACKER_ACCESS_TOKEN>
```

Показываются **текущая неделя и прошлая** — 14 дат в одном запросе. Опорный день по
умолчанию — дата сборки: его неделя (пн–вс) самая свежая, а сам он помечается как «сегодня».
Недели идут слева направо от старых к новым. Глубину меняет `BOARD_WEEKS_BACK`: `3` даст
четыре недели, те же 28 дат одним запросом.

Дни, по которым API не вернул отчёт, всё равно получают панель — с пустым состоянием из
макета. Открывается при загрузке **последний день с записями**, а не «сегодня»: сегодняшний
день обычно ещё не заполнен, и пустой первый экран ничего не сообщает.

## Токены

В `.env` лежат два: `FOOD_TRACKER_ACCESS_TOKEN` (запросы) и `FOOD_TRACKER_REFRESH_TOKEN`.
Access живёт около трёх часов, refresh — около месяца.

Автообновление по refresh-токену **не подключено**: эндпоинт обновления не найден — ни
`/api/*/token/refresh/` на `food-tracker.pht.space`, ни на `pht.space` (везде 404), а корень
`/api/` отдаёт только `v1/food-composition`. Похоже, авторизация живёт на отдельном хосте.
Как только известен URL, принимающий `{ refresh }`, обновление добавляется в
[src/lib/board-api.ts](src/lib/board-api.ts).

Пока access-токен нужно менять руками. Если он просрочен, сборка пишет в лог
`[board] ВНИМАНИЕ: access-токен истёк …` и берёт данные из кеша.

Каждый успешный ответ кешируется в `.cache/`, поэтому:

| Ситуация | Поведение |
| --- | --- |
| Обычная сборка | Запрос + обновление кеша |
| `BOARD_OFFLINE=1` | Сборка из кеша, без сети |
| Токен истёк / запрос упал | Предупреждение, откат на кеш, сборка проходит |
| Нет токена и нет кеша | Падает с понятным сообщением — данные никогда не выдумываются |

`.env` и `.cache/` в `.gitignore`: токены и дневник остаются локально.

## Настройки

Обязателен только токен. Значения из окружения приоритетнее `.env`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `FOOD_TRACKER_ACCESS_TOKEN` | — | Уходит в заголовок `Authorization: Secret <token>` |
| `FOOD_TRACKER_REFRESH_TOKEN` | — | Сохранён на будущее, пока не используется |
| `BOARD_DATE` | дата сборки | Опорный день; его неделя показывается первой |
| `BOARD_WEEKS_BACK` | `1` | Сколько прошлых недель добавить к текущей |
| `BOARD_WEEK_RENDER` | `20` | Передаётся в `week_render` как есть |
| `BOARD_CALORIE_GOAL` | `2700` | Цель для кольца калорий |
| `BOARD_CARB_TARGET` | `300` | Цель по углеводам, г |
| `BOARD_PROTEIN_TARGET` | `180` | Цель по белкам, г |
| `BOARD_FAT_TARGET` | `90` | Цель по жирам, г |
| `BOARD_OFFLINE` | `0` | `1` — сборка только из кеша |

**Нормы по калориям и макронутриентам — это настройка, а не данные API**: эндпоинт отдаёт
зоны рекомендаций по микронутриентам, но норм по калориям и БЖУ в нём нет. Всё остальное на
странице выведено из ответа.

Ссылки и фото — в [src/data/config.ts](src/data/config.ts): `FOLLOW_URL` (кнопка
«Подписаться»), `AD_URL` (баннер), `AVATAR_URL` (фото профиля из `public/`, пустая строка —
показывать инициалы).

## Соответствие API → интерфейс

| Элемент | Источник |
| --- | --- |
| Карточки приёмов пищи, по порядку | `meals[]` (только `is_enable`), сгруппированы по `meal` каждой записи |
| Название приёма | `meals[].name` с заглавной буквы |
| Подпись приёма | Сумма `metric_weight` + число позиций |
| БЖУ приёма | Суммы `protein` / `fat` / `carbohydrate` по его записям |
| Название и порция продукта | `food.name` + `serving.name_ru` + `brand_name`, либо `recipe_constructor.name` с пометкой «рецепт» |
| Калории позиции и приёма | `calories`, для рецептов — `recipe_constructor.nutrients.calories` |
| Бары БЖУ за день | Суммы по всем записям; цели из настроек |
| Кольцо калорий | Итог дня против `BOARD_CALORIE_GOAL` |
| Кольцо клетчатки | Метрика `110` из `recommendations.daily`, цель — её зелёная зона |
| Кольцо растительности | Метрика `1`, цель — её зелёная зона, пересчёт в кг |
| Точка в календаре | Есть ли за день записи |
| Имя в профиле | `first_name` / `last_name` из полезной нагрузки токена |

Три кольца настраиваются в `RING_METRICS`: `id` метрики, подпись, а также `divisor` / `unit` /
`decimals` — так растительность из граммов переводится в килограммы (делятся и факт, и цель,
поэтому дуга не врёт).

Кольца клетчатки и растительности стоят на местах, где в макете были шаги и вода: этих данных
эндпоинт не отдаёт, а у метрик рекомендаций есть настоящие цели из `zones`, так что показатели
выведены из данных, а не придуманы.

## Язык

Интерфейс полностью на русском: строки собраны в [src/data/strings.ts](src/data/strings.ts),
даты и числа форматируются локалью `ru-RU` (разряды — неразрывный пробел: «2 601»), для
числительных есть склонение — «1 позиция / 2 позиции / 5 позиций». Данные из API (названия
продуктов, единицы, заголовки зон вроде «Оптимальные рекомендации Физикл») приходят на русском
и подставляются как есть.

Комментарии в коде и имена классов оставлены на английском — это обычная практика и смешение
языков в идентификаторах читалось бы хуже.

## Замечания по переносу макета

- **Mobile-first.** Все правила написаны под телефон. Единственный медиазапрос
  (`min-width: 431px`) ограничивает кадр 430 px и добавляет тонкую рамку, так что на широких
  экранах получается центрированный «телефон» из макета.
- **Недели — карусель.** Каждая неделя занимает страницу с горизонтальным `scroll-snap`, в шапке
  «‹ 3 – 9 авг. 2026 ›». Свайп на телефоне работает без JavaScript; скрипт нужен только стрелкам
  и стартовой позиции (открывается неделя выбранного дня). На крайней странице соответствующая
  стрелка гаснет. Все дни — один ARIA-`tablist`, поэтому стрелки клавиатуры проходят все недели
  насквозь, а браузер сам подматывает нужную страницу к фокусу.
- **Переключение дней** — единственное, что требует JavaScript. Все панели уже в разметке,
  скрипт лишь меняет, какая из них `hidden`.
- **Аккордеоны приёмов пищи на `<details>`/`<summary>`** — без JavaScript, свёрнуты по
  умолчанию. Число позиций в подписи переключается через CSS по `[open]`.
- **Округление один раз.** Калории приёмов суммируются без округления и округляются только
  при выводе, поэтому итоги дня совпадают с API, а не расходятся на несколько ккал.
- **Значения макета не менялись**: цвета, радиусы, тени, кегли и геометрия кольца `2 × π × 52`
  перенесены из инлайновых стилей в токены. Кольца стали адаптивными, потому что их три.
- **Исправлены React-атрибуты** на настоящие SVG (`strokeDasharray` → `stroke-dasharray`,
  `strokeLinecap` → `stroke-linecap`).
- `image-slot.js` не переносился: это заготовка-скаффолд, а в макете нет элементов
  `<image-slot>`. `support.js` был React-рантаймом design-компонента — статическая сборка его
  заменяет.
- Добавлены поддержка `prefers-reduced-motion` и видимая обводка фокуса, чего в исходном
  компоненте не было.
